Tasks:Create a new .NET Aspire AppHost and a ServiceDefaults project.  Add Azure Table Storage to the AppHost using builder.AddAzureStorage("storage").AddTables("tables") (which automatically spins up Azurite locally).  Configure the Orleans hosting extension in the AppHost (builder.AddOrleans("default")) configured to use Azure Table Storage for both clustering and grain persistence.  Scaffold an ASP.NET Core Minimal API backend project linked to the AppHost via .WithReference().Phase 2: Core Orleans Grains & Storage SchemaObjective: Build out the virtual actor layout for managing rules, mock RAG context, and application evaluations.Tasks:RulesRegistryGrain: Manages the active rule set. Holds the raw Prolog text string (or structured representation) and a version hash in memory, backed by Azure Table Storage.ApplicationEvaluationGrain: Manages the state of a specific municipal application, storing its incoming text, extracted structured data, evaluation outcome, and audit trail.Mock "RAG" Grain (RAGContextGrain): Acts as a stubbed knowledge base that simulates fetching relevant regulatory context or policy snippets based on keywords.Phase 3: Unstructured Rules Ingestion Pipeline (Step 5)Objective: Transform plain-text human rulebooks into a structured schema definition and executable Prolog clauses.Tasks:Create an ingestion endpoint/method that accepts a raw text block of municipal rules.Prompt/integrate an LLM (using Semantic Kernel or Microsoft.Extensions.AI) structured output feature to parse the text into:A JSON schema defining expected application attributes.Valid Prolog facts and rules (.pl syntax).Pass the generated Prolog rules and schema payload to the RulesRegistryGrain to store them securely in Azure Table Storage.Phase 4: Application Processing & Mock RAG Integration (Steps 4 & 6)Objective: Ingest unstructured application text, pull context via the mock RAG grain, reduce it to structured data, and evaluate it.Tasks:RAG Hook: When an application text arrives, query the mocked RAGContextGrain for matching supplementary guidelines.Data Reduction: Use an LLM structured-output call combined with the schema generated in Phase 3 to map the unstructured application text into a clean JSON data object.Prolog Execution Bridge: Invoke the evaluation engine (using an in-process engine like C#Prolog or a lightweight local evaluator setup) passing the structured application facts and the active Prolog rules from the RulesRegistryGrain.Phase 5: LLM-Assisted Results Evaluation & Dashboard Verification (Steps 2 & 7)Objective: Interpret raw Prolog boolean/term outputs into a human-readable decision summary and expose everything through the Aspire/Orleans dashboards.Tasks:Result Interpretation: Feed the raw output of the Prolog engine (e.g., success/failure flags, matched clauses) alongside the original application text to an LLM to draft a clear, justified decision explanation for caseworkers.State Persistence: Save the final result payload back to the ApplicationEvaluationGrain state (persisted automatically to Azure Table Storage).Observability & Testing: Fire test requests through a quick Minimal API endpoint or .http file, verifying telemetry, logs, and actor states via the Aspire dashboard.
